# 主动断开控制

本机连接卡片的断开操作使用发布端 Socket.IO 事件 `clear_out`，线上编码为 `42["clear_out"]`：无参数，无 ACK ID，不等待应答。随后停止本地输入、视频和音频并释放当前 peer；不注销发布端，不关闭允许被控开关。网络发送失败时仍清理本地会话，并由已有的无人值守重连循环恢复信令。

依据：2026-09-23 对已安装的 macOS 官方客户端 `libstreamer.dylib` 做只读静态分析。x86_64 `__text` 偏移 `0xbbba0` 的函数引用 `signal connection clear room` 日志，在 `0xbbc15` 构造 `clear_out`，以空消息列表和空回调调用与其他 Socket.IO 事件相同的 emit 函数。没有设备 ID 或 peer ID 参数。分析文件和第三方二进制不纳入仓库。

此事件清除房间的控制连接，并非精确到单个 peer 的踢出接口。当前被控实现仅接纳一个活跃 peer，按钮与该会话的生命周期绑定，过期按钮请求不执行。如果以后增加同时多人连接，须重新设计单连接断开接口，不能直接复用房间清理。

自动测试验证精确报文、无 ACK 等待，以及同一发布端连接的心跳和 room_info 请求仍然可用。实际官方主控收到信令后的提示和再次连接需要端到端联调；静态分析及模拟传输测试不替代这项验证。
